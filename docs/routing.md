# Routing

> Traffic routing configuration for sing-box client configs generated by sbconfig.

## Overview

sbconfig allows users to configure **routing rules** that control how traffic is handled by the sing-box client. This enables powerful use cases like:

- **Blocking ads** from specific regions
- **Direct access** to local/regional domains (bypass proxy)
- **Blocking traffic** to/from specific countries
- **Split tunneling** based on domain, IP, or protocol

## Routing Concepts

### Outbound Types

| Outbound | Description |
|----------|-------------|
| `ssh-out` | Route traffic through the SSH proxy (default) |
| `direct` | Connect directly without proxy |
| `block` | Block/drop the traffic |

### Rule Matching

Rules are evaluated in order. The first matching rule determines the outbound. If no rules match, the `final` outbound is used (defaults to `ssh-out`).

```
Traffic → Rule 1 → Rule 2 → Rule 3 → ... → Final (ssh-out)
              ↓         ↓         ↓
           direct    block    ssh-out
```

## Routing Presets

sbconfig provides **pre-configured routing presets** for common use cases.

### Available Presets

| Preset | Description | Use Case |
|--------|-------------|----------|
| **Default** | Proxy all traffic, direct for private IPs | General use |
| **Iran Direct** | Iranian domains/IPs direct, ads blocked | Users in Iran |
| **Iran Block** | Block traffic to/from Iran | Privacy/security |
| **China Direct** | Chinese domains/IPs direct | Users in China |
| **Custom** | User-defined rules | Advanced users |

### Preset: Default

Basic routing - all traffic through proxy except private IPs.

```json
{
  "route": {
    "rules": [
      {
        "ip_is_private": true,
        "outbound": "direct"
      }
    ],
    "final": "ssh-out"
  }
}
```

### Preset: Iran Direct

For users in Iran who want Iranian websites to connect directly (faster) while blocking Iranian ads.

**Features:**
- Iranian domains (`.ir` and others) → Direct
- Iranian ads → Blocked
- All other traffic → Proxy

```json
{
  "route": {
    "rule_set": [
      {
        "tag": "iran-geosite-ads",
        "type": "remote",
        "format": "binary",
        "update_interval": "7d",
        "url": "https://github.com/bootmortis/sing-geosite/releases/latest/download/geosite-ads.srs"
      },
      {
        "tag": "iran-geosite-all",
        "type": "remote",
        "format": "binary",
        "update_interval": "7d",
        "url": "https://github.com/bootmortis/sing-geosite/releases/latest/download/geosite-all.srs"
      }
    ],
    "rules": [
      {
        "ip_is_private": true,
        "outbound": "direct"
      },
      {
        "rule_set": ["iran-geosite-ads"],
        "outbound": "block"
      },
      {
        "rule_set": ["iran-geosite-all"],
        "outbound": "direct"
      },
      {
        "domain_suffix": [".ir"],
        "outbound": "direct"
      }
    ],
    "final": "ssh-out"
  }
}
```

**Rule Set Sources:**
- [bootmortis/sing-geosite](https://github.com/bootmortis/sing-geosite) - Iranian domains
- [bootmortis/iran-hosted-domains](https://github.com/bootmortis/iran-hosted-domains) - Documentation

## Custom Routing Rules

Users can create custom routing rules using the following match criteria.

### Domain-Based Rules

```json
{
  "rules": [
    {
      "domain": ["example.com"],
      "outbound": "direct"
    },
    {
      "domain_suffix": [".ir", ".cn"],
      "outbound": "direct"
    },
    {
      "domain_keyword": ["google"],
      "outbound": "ssh-out"
    },
    {
      "domain_regex": ["^ads\\..+"],
      "outbound": "block"
    }
  ]
}
```

| Field | Description | Example |
|-------|-------------|---------|
| `domain` | Exact domain match | `["example.com"]` |
| `domain_suffix` | Match domain suffix | `[".ir", ".co.uk"]` |
| `domain_keyword` | Match if domain contains keyword | `["google", "facebook"]` |
| `domain_regex` | Match using regex | `["^ads\\..+"]` |

### IP-Based Rules

```json
{
  "rules": [
    {
      "ip_cidr": ["192.168.0.0/16", "10.0.0.0/8"],
      "outbound": "direct"
    },
    {
      "ip_is_private": true,
      "outbound": "direct"
    }
  ]
}
```

| Field | Description | Example |
|-------|-------------|---------|
| `ip_cidr` | Match IP CIDR range | `["192.168.0.0/16"]` |
| `ip_is_private` | Match private/LAN IPs | `true` |
| `source_ip_cidr` | Match source IP | `["10.0.0.0/24"]` |

### Port-Based Rules

```json
{
  "rules": [
    {
      "port": [80, 443],
      "outbound": "ssh-out"
    },
    {
      "port_range": ["1000:2000"],
      "outbound": "direct"
    }
  ]
}
```

### Protocol-Based Rules

```json
{
  "rules": [
    {
      "protocol": ["dns"],
      "outbound": "dns-out"
    },
    {
      "network": ["udp"],
      "outbound": "direct"
    }
  ]
}
```

| Field | Description | Values |
|-------|-------------|--------|
| `protocol` | Sniffed protocol | `dns`, `tls`, `http`, `quic` |
| `network` | Network type | `tcp`, `udp` |

### Rule Sets (Remote Lists)

Rule sets allow using pre-compiled domain/IP lists that update automatically.

```json
{
  "route": {
    "rule_set": [
      {
        "tag": "my-blocklist",
        "type": "remote",
        "format": "binary",
        "update_interval": "7d",
        "url": "https://example.com/blocklist.srs"
      }
    ],
    "rules": [
      {
        "rule_set": ["my-blocklist"],
        "outbound": "block"
      }
    ]
  }
}
```

**Popular Rule Set Sources:**

| Source | URL Pattern | Categories |
|--------|-------------|------------|
| **SagerNet GeoSite** | `https://github.com/SagerNet/sing-geosite/releases/latest/download/geosite-{category}.srs` | `cn`, `google`, `facebook`, etc. |
| **SagerNet GeoIP** | `https://github.com/SagerNet/sing-geoip/releases/latest/download/geoip-{country}.srs` | `cn`, `us`, `ir`, etc. |
| **Iran Domains** | `https://github.com/bootmortis/sing-geosite/releases/latest/download/geosite-{category}.srs` | `ir`, `all`, `ads`, `other` |

### Logical Rules (AND/OR)

Combine multiple conditions:

```json
{
  "rules": [
    {
      "type": "logical",
      "mode": "and",
      "rules": [
        { "domain_suffix": [".ir"] },
        { "port": [443] }
      ],
      "outbound": "direct"
    }
  ]
}
```

| Mode | Description |
|------|-------------|
| `and` | All conditions must match |
| `or` | Any condition can match |

## Database Schema

Routing configuration is stored in the settings table and per-user overrides.

```sql
-- Global routing preset
INSERT INTO settings (key, value) VALUES ('routing_preset', 'iran_direct');

-- Custom rules stored as JSON
INSERT INTO settings (key, value) VALUES ('routing_custom_rules', '[
  {"type": "domain_suffix", "value": [".mycompany.com"], "outbound": "direct"},
  {"type": "domain_keyword", "value": ["ads"], "outbound": "block"}
]');

-- Enabled rule sets
INSERT INTO settings (key, value) VALUES ('routing_rule_sets', '["iran-geosite-ads", "iran-geosite-all"]');
```

### Rust Models

```rust
#[derive(Clone, Copy, PartialEq, Serialize, Deserialize)]
pub enum RoutingPreset {
    Default,
    IranDirect,
    IranBlock,
    ChinaDirect,
    Custom,
}

#[derive(Clone, Serialize, Deserialize)]
pub struct CustomRule {
    pub rule_type: RuleType,
    pub value: Vec<String>,
    pub outbound: Outbound,
}

#[derive(Clone, Copy, PartialEq, Serialize, Deserialize)]
pub enum RuleType {
    Domain,
    DomainSuffix,
    DomainKeyword,
    DomainRegex,
    IpCidr,
    Port,
    Protocol,
}

#[derive(Clone, Copy, PartialEq, Serialize, Deserialize)]
pub enum Outbound {
    Proxy,   // ssh-out
    Direct,  // direct
    Block,   // block
}
```
